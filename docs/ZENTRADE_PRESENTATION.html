Architecture & Engineering Progress

ZenTrade

An autonomous senior trader for the Indian equity market.

Paper simulation only NSE equities Go · TypeScript · Python

01Executive overview

Most automated trading systems are rule engines: a condition fires, an order goes out. They cannot explain themselves, they cannot notice that their reason for holding a position has quietly stopped being true, and they cannot argue with themselves.

ZenTrade is built around a different premise — that the valuable part of a discretionary trader is not the entry signal but the continuous reassessment. A senior trader forms a view, writes down what would prove it wrong, watches the market, and changes their mind when the evidence changes. ZenTrade does that, autonomously, and shows its work.

Two things make it more than a language model with a broker attached. First, deterministic code owns every safety decision — risk, sizing, legality, arithmetic, and permission to execute. The model contributes interpretation and nothing else. Second, protection never waits for reasoning: a stop breach is acted on in microseconds by a separate process that has no model client linked into it.

It trades paper only. There is no order-placement code anywhere in the repository — the safety boundary is absence, not a setting.

02The two goals

Goal 1 — a senior-level autonomous trading agent

Not "the agent can output BUY, SELL or HOLD". The bar is behavioural: it maintains a live model of the market, notices when something material changes, forms a thesis, attacks its own thesis, considers what else could explain what it sees, prices the opportunity against real costs, checks whether the world moved while it was thinking, and keeps reassessing every position after every meaningful change.

Goal 2 — the right language for each workload

Not "rewrite it in Go". The instruction was to migrate only where there is a measured or structural reason, and to say so plainly where there is not. That discipline is why one component moved, one was rejected on a vendor constraint, one was fixed rather than migrated, and C++ was rejected outright with the numbers to justify it.

Three processes, three responsibilities, no overlap. The backend owns the vendor edge and the cockpit's transport. The agent owns the trading runtime. The fast plane owns the tick. None of them can do another's job.

05The life of one tick

A single price update from the exchange:

  1. Normalised at the edge. The vendor's float rupee value becomes integer paise and dies at this boundary. Timestamps become epoch milliseconds; receipt time and exchange time stay separate fields.
  2. Published onto Redis, where both the fast plane and the agent are listening.
  3. The fast plane updates the world. Last, high, low and a monotonic per-symbol sequence, in the shard that symbol hashes to — 28.99 ns, zero allocations.
  4. Levels are tested. If the tick crosses a stop, a target or a named invalidation the thesis pre-committed to, an event is emitted immediately.
  5. Material change is detected. Approach bands, price velocity over a real window, VWAP deviation, and volume inside the minute in progress.
  6. Nothing happens if none of that is true — which is the common case, and the system stays silent rather than manufacturing activity.

Emitted events reach the brain by push, not by poll: roughly a millisecond from the tick, not a drain interval.

06The fast plane, and why it is Go

The honest reason is not speed. Node evaluates the same reflex in 83 nanoseconds, which is fast enough. On the real detection workload Go is 1.24× faster — not a reason to migrate anything.

The reason is isolation. Tick receipt and protection used to share an event loop with model orchestration and HTTP serving, and a measured 86.8 ms of head-of-line blocking proved that coupling was real. They also shared a process lifetime, and the backend exits on any uncaught exception — so an unrelated bug dropped the market feed mid-session.

Why a language boundary rather than just a second Node process. A minimal Node process would isolate it today and drift back into a brain within a quarter, because adding an import is free. Across a language boundary, adding a model client to the deterministic safety path is not a temptation — it is a rewrite. The fast plane has no model client, no database driver and no order path linked into it, and cannot acquire one by accident.

07The Senior Trader Brain, and why it stays TypeScript

The reasoning pipeline is bound by the model, not by the language. Two sequential model calls dominate at seconds each; the orchestration around them is nanoseconds. Moving it to Go would make it no faster to run and considerably slower to change — and it is the part of the system most likely to change weekly.

The risk gate stays with it deliberately. Splitting a decision from the gate that authorises it across a process boundary adds a failure mode and buys nothing.

08The research plane, and why it stays Python

Point-in-time discipline, a 75.8-million-row bar spine, feature engineering, calibration, replay and backtesting all run on Polars and DuckDB — which are Rust and C++ underneath. Writing our own would be slower and less correct.

The research protocol is frozen and was not touched: 156 trials, a Bonferroni threshold of 3.178, and zero holdout looks. Rewriting the harness would put those numbers at risk for no gain.

09The C++ decision

No C++ was written, and that is the finding.

At a generous 1,000 ticks per second the entire fast plane consumes 0.0083 % of one core. The reflex is 0.0056 % of the protective path it feeds; the remaining 99.99 % is Postgres round trips against an instance whose bare SELECT 1 measures 322.6 ms. Optimising the reflex in C++ would be the wrong end of the problem by five orders of magnitude.

There is also nothing to compute. The system consumes last-traded price and cumulative volume. No spread, no book imbalance, no queue position — microstructure code with no microstructure data.

Where C++ would earn its place. Level-2 depth: 200 symbols × 20 levels × 2 sides, roughly 100× the message rate, with every message mutating a book rather than comparing a scalar. The boundary is pre-drawn behind the same frozen contract, with one precondition — build it in Go first and profile to saturation. If Go holds, the answer stays no. No speculative code exists.

A vendor constraint worth naming

The Fyers market-data socket speaks a proprietary binary protocol. The vendor SDK ships it fully obfuscated with no published schema. Reimplementing it in Go or C++ would mean reverse-engineering obfuscated code against a venue that cannot be exercised outside market hours. That is why the vendor edge stays in Node — a constraint, not a preference.

10Evidence hierarchy

A senior trader does not confuse "price is above VWAP" with "buyers are aggressive". The first is arithmetic; the second is an interpretation that may be wrong. Conflating them is how a weak inference acquires the authority of a measurement.

TierMeaningAssigned by
FACTMeasured or computed from data helddeterministic code
OBSERVATIONA measured comparison against a baselinedeterministic code
INFERENCEA conclusion drawn from factsthe model — its ceiling
HYPOTHESISA candidate explanation, not establishedthe model
PREDICTIONA claim about the futurethe model

Tiers are assigned by origin, never claimed. Anything the model produces is clamped to INFERENCE or weaker. It cannot promote its own reasoning to fact.

11Thesis architecture

  ORIGINAL THESIS                  CURRENT BELIEF
  written once at entry            rewritten on every reassessment
  immutable, append-only           the evolving view
        │                                │
        │  rationale                     │  action
        │  setup type                    │  thesis still valid?
        │  invalidation conditions       │  what changed
        │  stop, target, horizon         │  triggering event
        │                                │
        └────────── compared ────────────┘
                        │
                 has reality diverged
                 from what I believed
                 when I entered?

Keeping these apart is the whole point. A system that edits its entry thesis as the market moves cannot tell you it was wrong — it can only tell you what it currently believes, which is worth much less. The cockpit shows them side by side, and the entry thesis is enforced immutable at the database level.

12Adversarial reasoning

Forming a thesis is easy; a language model will produce one for any chart. The value is in the second pass, whose only job is to break the first.

ArtifactWhat it asks
Strongest objectionWhat is the single best argument against this?
Counter-thesisWhat would I trade instead, stated as a position?
Alternative hypothesesShort covering? Index beta? Thin liquidity? A single large order?
Disconfirming evidenceWhat in the data contradicts this view?
What would change my mindNamed, falsifiable conditions
Confirmation bias checkWas the author only looking for supporting evidence?

The challenger runs at near-zero temperature, so "this thesis is weak" is a stable judgement rather than a sample. It can only ever make the decision more conservative: a broken thesis cannot become a buy, and a weak one cannot open new exposure. And a thesis with no invalidation condition is not a thesis — the action is forced to HOLD.

14Continuous observation

The system used to poll every fifteen seconds. That is not a tuning problem, it is a category error: a poll samples endpoints and cannot see what happened between them.

  A price that moves 3.5% and returns within 14 seconds:

  15-second poll        t=0  ₹1,000        t=15  ₹1,000
                        ────────────────────────────────
                        "nothing happened"

  continuous            t=0  ₹1,000
                        t=7  ₹1,035   ← detected on this tick
                        t=14 ₹1,000

Eight conditions are now evaluated on every tick: stop, invalidation, target, stop approach, target approach, price velocity, VWAP deviation and volume. Only feed staleness remains timer-driven, and necessarily — the absence of ticks cannot arrive as a tick.

The supervisory scheduler still runs, but for what schedulers are for: reconciliation, order expiry, health and end-of-day. It is no longer how the system finds out that the market moved.

15Protective reflex

The governing idea: the line between the fast path and the slow path is not drawn by latency budget. It is drawn by who already made the decision.

A thesis is a pre-commitment. It named its stop, its target and the price that would prove it wrong, and the risk gate already authorised the position those levels belong to. When a tick crosses one of them there is no judgement left to make — so there is nothing for a model to decide.

BeforeNow
Stop breach noticed15-second pollthe tick that causes it
Thenqueued behind two model callsacted on immediately
Level lost → order exists≈ 35 seconds≈ 1 millisecond
Model consultedyesno

Reasoning still happens — afterwards, to decide what the crossing meant, not whether to protect. And only a crossing of a pre-committed level authorises action; everything else is an attention signal that wakes the trader without moving the position.

16Memory and learning

  trade → outcome → reassessment → calibration → future context
    │        │            │             │              │
  journal  labelled    evolving      how well       retrieved as
  entry    at a        belief        calibrated     OBSERVATION on
           horizon                   was I?         the next decision

Every decision is journalled with its evidence. Outcomes are labelled with strict no-look-ahead rules. Episodic memories index that experience, and retrieval surfaces comparable past decisions when a similar one is being made.

Two rules keep this honest. Retrieved memories enter as OBSERVATION, never as current market fact, and contradictory episodes surface together rather than the flattering one being shown alone. Eligibility is strictly before the deciding session, so a memory can never contain the outcome of the decision it is informing.

No alpha is claimed from this. It is context, and it is labelled as context.

17The autonomous runtime

  TERMINAL 1              TERMINAL 2              TERMINAL 3
  npm run dev             npm run server          npm run agent
  ─────────────           ──────────────          ─────────────
  cockpit UI              API + auth              ① checks deps
                          Fyers vendor edge       ② builds Go plane
                          bar aggregation         ③ starts it, waits
                          cockpit transport       ④ starts the trader
                          narration relay         ⑤ prints status
                                  ▲                       │
                                  └──── Redis ────────────┘
                                     narration + heartbeat

Exactly one autonomous runtime exists, and it lives in the agent process. The backend cannot start a second one — the code to do so does not exist there, and a test asserts it.

The split earns its keep: the trader restarts without dropping the market feed, and the cockpit reloads without disturbing the trader. The agent writes a short-TTL heartbeat, so the cockpit distinguishes a quiet trader from a stopped one and says TRADER NOT RUNNING rather than reporting ARMED.

18The live cockpit

Not a dashboard. The intent is the experience of sitting beside an autonomous trader while it works.

  WAITING FOR MATERIAL CHANGE          quiet market, genuinely quiet
        ↓
  FAST PLANE · MATERIAL CHANGE         teal — deterministic detection
        ↓
  MATERIALITY CHECK                    why it matters, or why it does not
        ↓
  SENIOR TRADER AWAKENED               amber — the model is now involved
        ↓
  WHAT DO I KNOW?                      evidence, tiered by origin
        ↓
  INITIAL THESIS  →  CHALLENGE  →  ALTERNATIVES  →  WHAT WOULD CHANGE MY MIND
        ↓
  DETERMINISTIC SYNTHESIS              R:R · cost hurdle · opportunity cost
        ↓
  DECISION  →  FRESH-WORLD REVALIDATION  →  RISK GATE
        ↓
  ORDER  →  FILL  →  POSITION  →  REASSESSMENT
        ↓
  RETURNING TO OBSERVATION

The rule the whole interface rests on: nothing generates activity. There is no timer, no synthetic event, no thinking animation. When the market is quiet the screen is quiet and says so. A value the system does not have renders as UNKNOWN; confidence with no stated basis renders as INSUFFICIENT BASIS.

The browser is read-only by construction — only GET endpoints, no import that can reach execution, and a test that fires every mutating verb at the running server to prove it.

This is the ordinary case, and it is the point. A system that only shows you its trades is hiding the decisions that mattered most — the ones where it declined.

21Why the model cannot trade

The model is one voice in a system that does not take its word for anything.

  model proposes  ──▶  deterministic validation   illegal action → HOLD
                  ──▶  adversarial challenge      can only be more conservative
                  ──▶  deterministic synthesis    arithmetic, never asserted
                  ──▶  fresh-world revalidation   is this still true?
                  ──▶  hard risk gate             deterministic, non-negotiable
                  ──▶  execution                  9-state machine, idempotent

The model never determines risk, legality, quantity, arithmetic, freshness or permission to execute. It cannot reach the execution engine — there is no path from the reasoning modules to it. A malformed response becomes HOLD. A model outage becomes HOLD. And the protective path, where a wrong answer is most expensive, does not consult it at all.

Live validation

Separate, and honestly reported: the system has never processed a tick from a live market session. Everything above is proven against a real database, a real cache, the real Go binary and the real reasoning pipeline — but not against a real exchange feed.

24Starting it tomorrow

  1. Re-authenticate the broker
    The token expires at 03:00 IST daily. Then run the preflight — it ends in READY or names the reason.
    cd apps/api && npm run preflight
  2. Start the cockpit
    cd apps/web && npm run dev
  3. Start the backend
    API, vendor edge, cockpit transport. This process does not trade.
    cd apps/api && npm run server
  4. Start the trader
    Builds and starts the Go fast plane, then the autonomous runtime.
    cd apps/api && npm run agent

Open http://localhost:5173/trader and watch. Stop with Ctrl-C in the agent terminal: it drains, reconciles, releases the market-data lease and exits cleanly.
